## 2025-03-09 - Optimized ArtifactStore.gc() performance
**Learning:** File operations that rely on dynamically calculated file lists/sizes can cause significant performance bottlenecks and hit `EMFILE` limits (too many open files) if executed fully concurrently across large datasets, especially if operations involve repeated async I/O stat calculations. Additionally, state calculation for file limits (like total space/count constraints) suffers from race conditions if executed concurrently during the building phase.
**Action:** When implementing or optimizing large-scale file removal flows (like garbage collection or cleanup jobs), build the removal queue sequentially or in heavily batched chunks (e.g., using `Promise.all` with a small slice like 10 items at a time) to avoid limits and resolve accurate final state, *before* executing the deletion. The actual removal logic (`fs.rm`) should similarly be batched.
