## 2026-07-24 - Optimize large file operations with batched concurrency and separated state queues
**Learning:** Optimization of operations that iterate over large numbers of files (e.g. ArtifactStore.gc) using batched concurrent fs.stat and fs.rm checks (e.g. Promise.all with chunk sizes of 10) prevents severe performance bottlenecks and EMFILE limits. When optimizing file operations that depend on dynamically updated cumulative totals (e.g., calculating removedBytes against a maxTotalBytes limit), first evaluate the files sequentially to build a safe removal queue. Only after the queue is built should the actual file deletions be executed concurrently in chunks to prevent race conditions during state calculation.
**Action:** When performing file system operations on a large collection of items, evaluate state changes synchronously to prevent race conditions, and then perform the IO sequentially in small concurrent chunks (e.g., chunk size 10) to avoid EMFILE limits while speeding up performance.
