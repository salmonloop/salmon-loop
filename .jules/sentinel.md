## 2025-02-09 - [Fix timing attack vulnerability in token validation]
**Vulnerability:** The authentication token validation in `serve.ts` was susceptible to a timing attack. Before calling `crypto.timingSafeEqual`, the code checked if the lengths of the provided token and the expected token matched (`tokenBuffer.length === authTokenBuffer.length`).
**Learning:** This length check created a short-circuit fast path. If lengths didn't match, it returned early. This allows an attacker to deduce the length of a valid authentication token by observing response times, aiding in brute-forcing. `crypto.timingSafeEqual` will throw an error if the buffer lengths don't match, so developers often try to check length first, inadvertently introducing the timing vulnerability.
**Prevention:** When comparing secrets (passwords, tokens, etc.), always hash both the provided value and the expected value using a cryptographic hash function (like SHA-256) first. This converts them to fixed-length representations (e.g., 32 bytes for SHA-256), allowing `crypto.timingSafeEqual` to be used safely without length mismatch errors and completely masking the original secret's length.
