## 2024-10-24 - Timing Attack Fix
**Vulnerability:** A timing attack vulnerability existed where user-provided tokens were checked against valid tokens using `crypto.timingSafeEqual` but only if their lengths matched. If their lengths did not match, it bypassed the timing-safe check and immediately returned false (implicitly). Furthermore, comparing buffers of different lengths via `crypto.timingSafeEqual` throws an error, which implies checking length first. However, early-exiting on length mismatch leaks the true token's length.
**Learning:** Comparing authentication tokens correctly requires avoiding fast paths that exit early upon observing length differences. The typical pattern `token.length === validToken.length && timingSafeEqual(token, validToken)` leaks length information.
**Prevention:** Hash the user token and the stored valid token to a uniform length (e.g., using SHA-256) and then compare those hashes using `crypto.timingSafeEqual`. This ensures the comparison time is independent of the input length and effectively neutralizes length-based fast paths.
